Stage 1

Interaction foundations

Shared entity semantics, command activation, selection and feedback underpin every tool.

Command and gesture contract

Tools operate on entities, their components and groups, including imported models. File formats do not define a separate editing workflow. The entity supplies capabilities and constraints; the editor coordinates selection, preview and history.

Every operation is available through public API. Keyboard shortcuts, configurable modifiers and host buttons invoke the same command state; no synthetic key events are required. The host owns application layout. The scene shows only the active handles, guides and relevant values.

StateContract
HoverIdentify a valid target without changing geometry.
PressLock the target and operation; movement starts after the drag threshold.
PreviewUpdate geometry feedback, snapping and metrics without committing the document.
Confirm / cancelCommit one Undo step, or restore the original state. Both actions have public API.

Focus loss, invalid document revisions and navigation conflicts must follow the same cancellation rules. Tool activation alone never edits geometry. Confirmation, cancellation and reference picking share one operation lifecycle.

Selection and overlap priority

Component picking follows entity capabilities and the active editing scope. Imported models start in whole-object scope; locked objects are excluded. The following part-selection examples apply only when component editing is available.

Selection is always amber. A dot marks a vertex, a thick line an edge, and a translucent fill a face; the whole object's outline stays muted amber.

At overlapping points or edges, the selected entity owns the hover target. Press locks that target for the entire gesture.

Locked objects

Locking prevents ordinary selection, deletion, reparenting and geometry, transform or parameter edits. At rest there is no scene badge. Hover over a locked object shows a small informational lock beside the pointer, without a selection highlight or editing handles. It disappears when the pointer leaves.

The hover lock is not a button and never captures the pointer. Unlock is a context-menu command on the locked object, or an action in the host object list or public API. A context target need not be selected. The host list may show locks permanently. Ordinary click, box and lasso selection exclude locked geometry; visible locked objects may still provide read-only snap references.

Locking an active target cancels its preview and removes affected items from selection. A locked parent also protects its descendants; a child cannot override the inherited lock. Unlocking a parent preserves each child's own lock. Lock state is saved with the document and changed through undoable commands. Visibility and isolation never change locks.

Imported models: object scope first

Every imported model starts as one manipulation scope, or as a group preserving its hierarchy. This applies to STEP, STL and other formats when their importers are available. A mesh representation does not imply automatic vertex editing. Normal selection, move, rotate and scale act on the whole selected model.

Enter component editing explicitly through API or host controls. The entity advertises available vertex, edge, face, mesh or parametric operations. Unsupported operations stay unavailable with a reason. Opening a group's children does not automatically enable geometry editing. Read-only or locked models cannot enter component editing.

If editing requires conversion or tessellation, show the representation change and required tolerance before confirmation; do not silently discard exact surfaces or assembly structure. Keep world placement, material, layer and stable references where possible, and report references that cannot survive conversion. Finish or cancel an active gesture before leaving component mode. Leaving the mode keeps confirmed edits and returns to whole-model interaction.

Isolate the working set

Isolate the current selection to work without surrounding geometry. One or several entities, including groups, can form the isolated set. A component selection isolates its owning entity, not a detached vertex or face. Hidden surrounding entities cannot be picked, snapped to or used as automatic Extend/Trim candidates.

Isolation is a per-viewport visibility filter on top of document and layer visibility, not repeated Hide/Show commands. Exit removes only that filter. Existing hidden objects and hidden group children stay hidden; explicit visibility changes made while isolated remain in effect. Locks and layer settings are never reset. Geometry edits remain normal Undo steps; entering or leaving isolation does not create a geometry edit.

A compact “Isolated · Exit” indicator remains in the viewport; it is a state control, not a floating tool menu. The same enter, replace-set and exit actions are public API for host controls. The first version uses one isolation level: replacing the set does not stack hidden states. Newly created or duplicated entities join the working set, subject to their layer visibility, so they remain visible; deleted entities are removed from it. An empty set keeps the Exit control available.

Entering or leaving isolation cancels an active preview before changing visibility. Exit does not select newly revealed objects or move the camera. Loading another document resets isolation. Scene helpers such as the active grid remain available; the document objects outside the working set do not.

Cursor lifecycle

Hover offers an operation. Press locks the target and replaces the pointer; dragging starts once the threshold is crossed.

Markers and visual language

Amber identifies selection or the active edit. Neutral snap markers describe a geometric relation; axis colors describe directions. Red with a removal mark is reserved for deletion previews. Temporary guides are dashed and never look like persistent geometry.

An origin uses a ring with a dot; a temporary transform pivot uses a diamond. A square snap marker is temporary and does not change a vertex into a square handle. These semantics apply in both themes.

Context metrics and measurement

The entity supplies a simple readout for the target and operation. An active gesture takes priority over hover, and hover over selection. When the cursor leaves, the selection readout returns; with no target, it disappears.

Multiple selection: count only, e.g. “8 vertices” or “3 objects”, or no readout. No combined bounds or totals. During manipulation, movement delta, rotation angle or scale ratio takes priority.

Values are illustrative. The document controls units and precision, not pixel size. The host may hide the standard display and use the same API in its own UI.

Stage 2

Coordinate systems and transforms

Establish the reference frame, then apply the same transform tools to entities and their editable components.

Frames and working planes

World, document and local frames must be explicit. A working plane has an origin, in-plane axes U/V and normal N; changing it does not transform existing geometry.

Its finite display rectangle is independent of the mathematical plane and grid step. Ordinary plane bounds limit display only; an explicitly bounded drawing area rejects new points outside it. Tilt uses the plane axes or a chosen straight edge.

Origins: scene and entity

An origin is the permanent coordinate-system origin, not a vertex, snap marker or temporary operation pivot. It uses a neutral target marker with short colored axes. It is amber only when selected for editing.

“Edit origin” activates a move or rotate gizmo for the coordinate system only. “Define origin” lets you snap to a point, choose the bounding-box center or enter XYZ. Choosing a point alone preserves orientation; two optional extra points define X and the XY plane.

The object, its children and nearby geometry stay in place when the origin changes. Scene origin here means the document's user coordinate system: it does not overwrite geographic coordinates, CRS or the internal rendering origin. Temporary pivot and measurement reference are set separately.

Confirm saves one Undo step; cancel restores the original coordinate system. Display, definition, movement and orientation all have public APIs for host application buttons.

Move

A dashed outline distinguishes a plane handle from actual geometry. Hover strengthens its fill and both corresponding axes; axis lines remain solid.

At rest, only axes and center are visible. Larger XY/XZ/YZ handles appear near the pivot; the active plane remains during dragging.

Rotate

Three XYZ rings. Hover selects an axis; dragging shows a sector and the current angle.

Scale

Selection determines what changes; the handle determines which dimensions change. An axis end scales one dimension, a plane handle scales two by a shared factor, and the center square scales all three uniformly. None of these handles implicitly selects a face.

Live dimensions and reanchor

The active handle shows signed distance, angle or scale ratio in document units. A plane move shows two components; a face move uses its normal. Changing the measurement reference is separate from moving the transform pivot.

Right-click without dragging offers “Change reference”. The preview holds; the next click selects a point, midpoint, intersection or unambiguous point on an edge or face. Movement then continues without holding a button; click or Enter confirms. Esc while selecting a reference returns to the original preview.

For scale, the ratio stays primary; a reference length allows a target size in mm. Rotation uses a reference direction, not just a point. “Move pivot” is a separate command; choosing it alone must not change the current geometry.

Component editing

Within an enabled component-editing scope, a vertex, edge or face edits shared geometry; the whole-entity handle changes the entity transform. Direct vertex drag uses the view plane. A click without dragging instead exposes its manipulator; axis and plane controls follow the Move rules.

Precise placement

Choose a source point on the entity and a target point or surface. This moves the entity as a whole, not the source vertex. Surface-normal alignment is a separate option.

Stage 3

Drawing and geometric edits

Build entities on explicit planes or in 3D, then use shared snaps and local parameter tools.

Drawing primitives

Lines and polylines may have independent XYZ vertices. Rectangles, circles and arcs retain their own plane even when tilted. Closing a spatial path does not implicitly create a planar face.

Snap to occluded geometry

A visible object's far-side edges and vertices remain potential snap targets even when its faces occlude them. This is different from an object hidden explicitly, by its layer or by isolation: those objects provide no snap targets. Occluded snapping is a shared setting available through the tool API and host controls, separate from X-ray selection.

Reveal the nearby candidate edge and enough faint connected edges to explain its depth; do not expose the entire model as a permanent wireframe. Only occluded spans are dashed; visible spans remain solid. The active snap mark stays neutral and uses the usual endpoint, midpoint or other relation shape. Do not make an occluded edge solid when it wins.

Candidate order respects explicit target scope and selected-entity priority. Within otherwise equivalent candidates, prefer the visible target; offer stable next/previous candidate cycling through API and host controls for overlaps. An occluded candidate must be visually revealed before confirmation, never silently chosen through a face. Press locks the chosen target; the stored snap uses its actual 3D position and identity, not its screen projection.

Active plane and axis constraints still apply: reject an incompatible rear point rather than projecting it. Locked visible models can provide these references without becoming selectable or editable. Imported models can expose snap geometry without entering component-editing mode. No candidate overlay changes visibility, locks or entity geometry.

Tangency and persistent references

A snap may target the grid, a free point or a geometric feature. Entity references can persist as constraints and follow subsequent edits; they must preserve target identity and detect invalid or cyclic dependencies. A live snap preview does not need a second set of visual markers.

Circle diameter

Ordinary outline drag moves the circle. Activate diameter editing through its API, a host button or a configurable modifier; then start from any point on the selected circumference. The center stays fixed and its handle remains a move handle.

The circle plane is fixed, but the radial direction follows the pointer to allow point and tangent snapping. During the drag, the cursor is a radial double arrow without the pointer arrow. Ø reports actual diameter; ΔØ is twice the radius change. The original outline is dashed.

Numeric input sets diameter. Crossing the center never creates a negative diameter or flips the circle. Near edge-on views disable unreliable dragging and offer numeric input or plane-aligned viewing.

Automatic Extend and Trim

No boundary preselection is required. Hover identifies the target end or interval. Visible line segments also contribute their infinite supporting lines, so one line can extend to a virtual intersection before the other reaches it.

Extend chooses the nearest positive intersection and changes only the target entity. Trim removes only the existing interval under the cursor, shown in red with a cross. Each confirmed step recomputes candidates. Next/previous candidate selection is available through API and host controls.

Coincident candidates are merged; parallel, collinear or skew lines must not produce invented intersections. A missing cut interval does not silently delete the entire entity.

Offset, Split and Join

Offset creates a parallel contour, Split preserves both parts, and Join connects compatible endpoints. Each operation preserves entity identity and references where applicable, or explicitly remaps them.

Stage 4

Topology and local mesh editing

Shared topology comes before deformation. Converting one face must not silently convert its neighbors.

Face conversion and boundary constraints

Convert only the selected face and preview its subdivision before confirming. Render triangles of neighboring faces are not automatically editable topology. Shared boundaries remain constrained by the adjoining regular faces.

Mesh editing tools

After conversion, add local detail, select components and apply precise or soft edits. The perimeter is pinned by default. Padlocks mark pinned boundaries only while editing the mesh; they are not snap markers or idle object badges.

Soft drag uses the usual axes, planes or the normal at the grab point. Its radius follows the mesh surface, not just distance in space; the circle shown is an example on an initially flat face. On a curved mesh, the influence boundary follows the surface. Point intensity shows a smooth falloff.

Set radius and strength with the mouse or API. Confirm the preview as one Undo step; Esc reverts it. Releasing the boundary must respect adjacent faces. Invalid deformation is rejected without creating a gap.

Push/pull and smoothing brushes are later extensions. The first set uses a single soft drag, not repeated deformation while painting. Automatic refinement and textured brushes are outside this phase.

Stage 5

Boolean operations and composition

Reuse the established entity, command and history contracts rather than creating parallel interaction systems.

Union, Difference and Intersection

Activate the operation through the shared tool API or host controls, then select compatible operands. For Difference, identify target A first and cutting operand B second; show A/B labels and offer Swap. Preview the complete result before confirmation. Amber is retained geometry; red with a cross is removed material.

GeometryMeaning
Closed coplanar curvesUse their enclosed regions. Preserve arc segments where the representation supports exact curves; a result may have holes or several disconnected regions.
Open pathsNo enclosed area: use Join, Split, Trim or Extend. Do not silently close a path to make a region.
Valid closed solidsUnion, subtraction or common volume. Availability comes from entity capabilities and the geometry backend, not from the object's screen silhouette.
Open meshes or noncoplanar facesDo not offer a volume Boolean by default. Surface intersections or slicing need a distinct supported operation; never silently project or cap the inputs.

Circle Boolean results are regions bounded by arcs, not circles with a changed radius. Join connects compatible path endpoints; it is not Union. Cut here means A minus B. A plane slice that keeps both sides is a separate Split operation.

Inputs remain intact until confirmation. The default result replaces the participating operands in one Undo step; Keep inputs is an explicit option. No overlap, empty intersections, tangency, containment and coincident boundaries must have clear previews. Reject empty or no-op results rather than silently deleting inputs. Point-only contact creates no zero-area face or zero-volume solid.

Operate on world geometry in a compatible frame, independent of camera projection. Validate tolerance, winding, holes and shared topology. Preserve unaffected identities; remap or explicitly report references to replaced parts. Locked operands can serve as references only when retained. Mixed or unsupported selections explain why the command is unavailable instead of performing a partial Boolean.

Copy, Mirror and Repeat

Copy preserves the original and creates new identities. Mirror and Repeat are subsequent capabilities: they preview the full result and commit or cancel as one operation.

Input mapping · pending specification

The remaining design pass defines left/right/middle mouse buttons, wheel and keyboard modifiers for each operation state. Wheel input may adjust rotation, scale, brush radius or other active parameters instead of zoom, but the active meaning must be explicit. Navigation and editing must never consume the same gesture twice.

Specify Windows/Linux Shift, Ctrl and Alt alongside macOS Shift, Control, Option and Command. Do not assume Command is a universal replacement for Control. Include trackpads, text entry, focus, modifier release during a drag and mouse-only host controls. Every mapping invokes the same public tool API; no command depends on a shortcut.

Design status and validation

This is the target interaction design, not evidence that all operations are implemented. Captions explain illustrations; they are not permanent scene UI. Input mappings remain to be specified before implementation is accepted.

Verify hover, activation, drag, confirmation, cancellation and Undo/Redo from all viewing directions, in both themes. Mouse, keyboard and API activation must produce equivalent results. Validate geometric edge cases, shared boundaries, reference preservation and rollback independently of visual feedback.
